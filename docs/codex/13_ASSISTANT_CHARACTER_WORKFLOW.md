# 助手形象创建和更换流程

本文记录博客助手的素材、动作播放和更换步骤。形象与文本问答服务独立：更换角色不需要修改数据库、供应商密钥、检索、预算或提问接口。当前版本使用有限姿态帧，不是 Live2D、骨骼动画或语音口型同步。

## 当前素材和动作

身份参考是 `public/assistant/chibi-v1.png`：原创黑金短发、耳麦、夹克、短裤和靴子的 Q 版角色，不使用游戏角色素材。使用内置 imagegen 生成新素材，要求真正透明背景，保存 PNG 的 alpha 通道，不用背景色模拟透明。

`public/assistant/chibi-actions-v3.png` 是 1254×1254 的 RGBA 图集，6 列×6 行，每格 209×209。按行从左到右播放六个姿态。第一行是双臂自然下垂的待机，包括睁眼、半闭眼、闭眼和重新睁眼；其他行也从下垂姿态开始。`public/assistant/chibi-idle-v3.png` 是 1024×1536 的静态下垂姿态，图集加载失败时使用。

| 行号 | 动作 | 时长 | 播放行为 |
| --- | --- | --- | --- |
| 1 | 待机和眨眼 | 6 秒 | 长时间保持睁眼，在末段眨眼，循环 |
| 2 | 挥手 | 1.8 秒 | 抬臂、挥手、落臂，然后回到待机 |
| 3 | 点头 | 1.5 秒 | 低头、点头、抬头，然后回到待机 |
| 4 | 思考 | 2.4 秒 | 抬手托腮、轻微歪头、放手，循环；检索时自动使用 |
| 5 | 鞠躬 | 2 秒 | 渐进前倾、低头、起身，然后回到待机 |
| 6 | 开心回应 | 1.8 秒 | 抬起前臂、笑眼、放下手臂，然后回到待机 |

每组六张姿态帧，额外的第七个播放节点返回第 1 行第 1 格，共 36 张素材姿态。真实图片的细节可能有轻微差异；这不是连续补间渲染。角色容器固定不动，只切换眼睛、手臂、头部和身体姿态的可见图格。

## 素材创建

1. 先确定原创或已授权的角色参考。记录来源与使用范围，不默认获得商业或第三方游戏素材授权。
2. 查看参考图，明确发型、衣服、配色、比例等不可改变的特征。将动作需求与身份参考分开。
3. 使用 `docs/assistant/chibi-v3-prompts.txt` 中的完整提示词作为模板。图集必须固定网格、统一中心与脚底基准线、完整人物及留白；首帧必须双臂下垂。避免文字、网格线、额外道具和整幅图平移。
4. 通过内置 imagegen 生成透明图集和静态回退。检查行列数、每格是否越界、手臂姿态、人物比例、眼睛/头部过渡和 alpha。若不符合，针对问题重新生成；不能只用 CSS 平移假装人物动作。
5. 将选定 PNG 复制到仓库 `public/assistant/`，使用新的版本文件名，例如 `chibi-actions-v4.png`，保留之前版本便于回滚。生成器默认目录不是生产文件来源。
6. 同步保存最终提示词、原始尺寸、行列数、动作顺序和验收结果，不记录密钥或服务器私有数据。

## 更换形象和接入

`src/lib/assistant/character.ts` 是形象配置入口，集中记录图集路径、原始尺寸、网格、动作行、时长、循环和时间节点。更新这里而不是分散修改所有页面。动作名称保持 `idle`、`wave`、`nod`、`thinking`、`bow`、`cheer` 可以直接复用交互。

`src/components/assistant/chibi-assistant.tsx` 中的 `Character` 使用浏览器动画 API 切换图格，无角色整体 transform。首次页面和首次对话默认待机。点击角色点头，也可以点击动作按钮；非循环动作完成后恢复待机。暂停、系统减少动态效果、隐藏页面或关闭对话时取消动画，显示双臂下垂首帧。不支持动画 API 时保留静态首帧。更换静态回退时也要同步组件中的路径与尺寸。

组件样式在 `assistant-panel.module.css`。图集大小由网格配置自动计算，不需要为每个新角色重复写关键帧。保留移动布局、对话滚动、键盘焦点和动作暂停控制；不要为了增大角色挤掉发送框。浏览器高度不足时隐藏装饰角色，聊天继续可用。

悬浮图集的透明左右边距不接收点击，人物区域和“聊聊”按钮仍可点击。更换角色时重新测量所有姿态的可见边界，并同步 `clip-path` 点击区域；不要让透明方框挡住下层文章缩略图。当前图集左侧保留 13%、右侧保留 10% 的可穿透区域。

## 验证和发布

运行 `npm test`、`npm run lint`、`npm run typecheck`、`npm run build`。本地数据库无配置时，用既有 `UI_PREVIEW_MODE=true` 预览，不能把预览模式带进生产。

启动本地生产预览后运行 `scripts/verify-chibi-assistant.mjs` 与 `scripts/verify-assistant-readability.mjs`。它们模拟回复，不调用付费模型，验证 320/390px 手机与桌面、动作六帧、回到待机、容器固定、暂停/减少动态效果、回退、对话/引用/错误恢复、焦点和缩放模拟。100%/90%/80%/200% 是 CSS 视口和像素密度模拟，不能当成实体手机或浏览器工具栏验收。

按所有者 2026-10-04 指示，后续在自动检查通过后直接提交、合并和部署，不再等待人工审查确认。仍保留 Git 历史、CI、磁盘/健康检查、备份和回滚保护；“不留存审查过程”不意味着删除这些安全记录。部署前确认服务器版本、工作区清洁、镜像可回滚和持久上传目录。此切片只替换应用，不改 Nginx、环境、数据库或上传 ACL。

部署后通过真实 HTTPS 检查新素材、默认下垂、动作选择、暂停、手机对话和问候；同时回归文章图片、整卡点击及高德地图。问候走已有本地回答，无供应商 token。检查失败恢复上一应用镜像，不还原数据库覆盖新内容。验收日志留在服务器运维目录，公开文档只记录非敏感结论。

## 当前限制

动作采用低帧数离散姿态，不承诺 60 帧连续动画或完全无细节漂移。若以后需要高质量连续动作，应使用有授权的可编辑分层模型或专业逐帧素材，再更换播放器。语音输入、语音播报和口型同步仍是独立功能，不因更换形象自动开放麦克风。
