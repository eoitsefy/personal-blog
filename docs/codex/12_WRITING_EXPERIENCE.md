## 1. 功能与数据边界

| 能力 | 行为 | 限制 |
| --- | --- | --- |
| 自动保存 | 停止输入约 1.5 秒后保存管理员私有工作副本 | 不更新正式文章、媒体引用、搜索或 AI 索引 |
| 新文章工作副本 | 允许标题、slug、正文尚未填完 | 每位管理员只有一个新文章副本，多窗口冲突不会静默覆盖 |
| 编辑中恢复 | 重开时选择窗口暂存、服务器副本或当前文章 | 不自动恢复、不自动发布 |
| 断网保护 | 当前标签页 `sessionStorage` 暂存与离开提醒 | 解析时拒绝超过 7 天的暂存；不是离线 PWA，不保证关浏览器后可恢复 |
| 并发保护 | 副本版本号及文章 `updatedAt` 检查 | 冲突返回 409，需保留/复制内容后重新打开，不自动合并 |
| 版本历史 | 正式保存前后记录不同快照，最多 20 个 | 旧文章从首次编辑开始记录，不追溯此前历史；不记录每次按键 |
| 恢复版本 | 载入编辑器并设为草稿 | 手动保存为草稿会撤下原公开文章，恢复本身不修改线上文章 |
| 图片粘贴 | 一次一张 JPEG/PNG/WebP，复用现有上传验证 | 上传目录仍公开；单文件限制沿用服务器配置，前端硬上限 20 MiB |
| 正文预览 | 同一 Markdown 渲染器；桌面双栏、手机上下排列 | 不是富文本编辑器，不执行任意 HTML |

工作副本限制正文 200,000 字符、媒体 ID 20 个、地点 ID 10 个，仍受 API 的 256 KiB JSON 请求总大小限制（中文 UTF-8 字节数可能先达到总限制）。正式提交继续校验 slug、分类/标签、媒体和地点有效性。

副本按用户 ID 与文章 ID 隔离；其他管理员无法通过工作副本接口读取别人的未提交输入。正式保存的历史版本则属于文章，所有管理员均可查看。所有新接口要求管理员会话，写请求继续执行来源、类型和大小校验，响应禁止缓存。

副本/历史只保存文字和关联 ID，不额外增加媒体引用计数。上传后未正式保存的文件可能仍显示“未引用”，不能据此断定没有工作副本使用它。历史恢复不复活已删除的媒体/地点；应先检查关联，再正式保存。永久删除文章或删除用户时按关系级联清理相应副本，文章历史随文章永久删除；软删除期间接口拒绝访问。

- `braces <=3.0.3` 的安全公告当前没有官方修复版本；不采用审计建议中破坏性降级 Next.js 配置的做法。该链不进入 `npm ci --omit=dev` 的最终应用依赖，但仍应在隔离 CI 中检查不可信代码并跟踪上游修复。
- CI 新增生产依赖审计门槛。生产审计为 0 不等于整个应用没有安全风险，地图的既有 CSP 兼容例外并未在本次消除。

核验来源：[Next.js 16.3.8 发布记录](https://github.com/vercel/next.js/releases/tag/v16.3.8)、[deepmerge-ts 8.0.0 发布记录](https://github.com/RebeccaStevens/deepmerge-ts/releases/tag/v8.0.0)、[braces 安全公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)、[Node.js 版本生命周期](https://nodejs.org/en/about/previous-releases)。上述审计结果是当日快照，后续应重跑。

## 4. 部署与验收流程

本次授权部署按以下流程实施，具体已验证和待人工复验的范围以第 7 节为准；后续部署仍需重新核验实时状态，不能复用旧验收结果。

1. 审查、推送、通过 CI 后合并；先在 Linux 构建 Node 24 镜像并测试 Prisma 与 sharp 原生组件。
2. 检查磁盘余量，保存旧应用镜像及提交；备份并验证数据库和 uploads，不删除正在使用的镜像/卷。
3. 使用新镜像执行 `prisma migrate deploy`，只新增 `PostWorkingCopy`、`PostRevision` 表与关系，不修改现有文章状态或正文。
4. 仅替换应用容器，保留现有数据库、媒体挂载、地图与 AI 凭据；健康检查后进行管理员新建/编辑与手机验收。
5. 特别验证：编辑已发布文章后不点“保存”时，游客与 AI 仍看到旧内容；刷新可恢复；第二窗口不会覆盖第一窗口；恢复历史不立即撤下文章；正式保存及媒体引用正确。
6. 回归登录、文章阅读、媒体上传、评论、地图、AI 与备案页脚，确认无 500/资源丢失后记录生产提交和证据，再更新两份功能文档。

回滚只切回旧应用镜像及提交，不删除新增表，不恢复整库覆盖新写入。新增表不影响旧代码；新编辑界面暂时消失，但已保存的工作副本/历史仍保留。回滚不能撤销部署后用户主动修改的文章；这种恢复应单独确认。
