# 助手动画样片 v6：制作前美术门禁

## 2026-10-05 所有者决定：接入两个样片，保留缺陷记录

所有者在收到“眨眼初步通过、挥手存在灰色手掌与重影”的结果后明确要求：“可行。将这两个动作直接部署，并跟进其他动作制作”。因此保存独立 `owner-acceptance.json`，决定为 `OWNER_ACCEPTED_WITH_KNOWN_ART_DEFECTS`，仅绑定本轮眨眼/挥手的有序像素摘要。**下面的原始美术拒收结果和严格技术门禁不被删除或改成通过。**该确认不适用于之后产生的任何新动作或改动帧。

公开运行时使用 15 fps 样片的偶数索引母版：眨眼 9 个时间线节点、挥手 31 个节点；RIFE 插值不是独立画师逐帧绘制。两动作使用一个固定 366×460 裁剪框去除透明留白，原始 768×768 母版保持；图集静态无损 WebP，按完整姿态换帧，不追加整图淡化。规范、哈希、大小与真实帧索引见 `runtime-manifest.json`。暂停、减少动态效果、按需加载、共享中立与原五个其他动作继续保留。

本地 136 项单元测试、lint、类型检查及构建通过。四宽度逐帧门禁各检查 153 个节点，完整头脚、固定视口、共同中立、快速切换、高密度、暂停/减少动态效果与失败回退通过。聊天模拟、焦点/Escape、错误恢复、字体缩放模拟通过。检查发现画布初始比例变化会产生全局减少动态效果规则触发的 0.01ms CSS 过渡，画布已单独设为无 CSS 过渡，重跑后通过；不是掩盖实际角色播放的动画。线上部署与实际 HTTPS 验收仍以之后的部署记录为准。

另制作一组双臂自然下垂的表情型哈欠：4 个内置 imagegen 关键帧、RIFE 生成 21 张 PNG，存放 `followup-yawn/`，不导入公开播放器。初次嘴部范围带入下巴轮廓，缩小口部编辑区域后重跑；其美术结论、技术证据和提示词单独记录。保留以后掩嘴哈欠的原动作规范，不能将表情版冒充完整掩嘴动作。

## 固定规则（制作前设立，不能因结果不佳而放宽）

- 所有导出的 PNG 均为 768×768、真实 alpha；四周至少 20% 安全边距。全动作共用同一画布和一次确定的缩放，禁止逐帧自适应裁切、缩放及拉伸人物。
- 中立原图、首尾帧完全一致；脚底锚点固定。原始 v4/v5 文件不得改动。
- 眨眼只能改变眼睑与眼部极小范围。挥手只能改变指定的一只手臂、相邻衣袖与必要的遮挡；不晃动整个人物，不改动脸型、发型、耳麦、服装设计和头身比例。
- 静止区域原图对照不允许可见形变。固定脚底测量偏移不得超过 1 源像素；透明安全边距内不得出现不透明人物像素。
- 不能出现新增/消失手指、断肢、衣袖穿模、融化轮廓、双影、眼睛跳变或发饰消失。RIFE 只补充小幅变化，不承担重新绘制解剖结构的责任。
- 真实 alpha 与颜色应在白、奶油、深灰、品红底检查；不得有邻格泄漏、大片白/黑边、彩色溢出、明显锯齿、独立杂点或透明孔洞。不得硬去色而误删黑色衣服或黄色发饰。
- 以真实 PNG 换帧播放，不把整图半透明渐变当作补帧；分别检查 15/30 fps、正常/半速、200/400 CSS 像素、DPR 1/2，首尾循环、暂停和逐帧检查。

## 严格放行方式

自动检测只说明几何、透明度和播放器行为，不等于美术通过。必须保存全帧联系表、浅/深底放大图、实际浏览器截图与逐项美术意见。任何一个关键问题即判该样片 `REJECTED`，不能用平均分覆盖；未看完所有关键帧与插值帧时标记 `PENDING`。两样片分别判定，不能一起宣称合格。

即使样片技术与美术通过，本轮仍只交付离线预览；正式接入须经过所有者确认。

## 免费路线与事实边界

使用现有内置图像生成能力制作受参考约束的关键帧；固定画布预处理和 PNG/alpha 质检用现有本地工具。尝试官方便携版 RIFE 在本机 GPU 上补帧，保留原始 PNG，不安装全局运行环境。未实际运行的 LoRA、ControlNet、IP-Adapter、EbSynth、ToonCrafter 或自动抠图模型，不得列为已使用。

本报告的实际结果、输出数量、失败例、尺寸和文件体积待制作及检查后填写。不承诺每动作小于 200KB 或整体小于 1MB。

## 实际结果：不准部署

实际使用**内置 imagegen + 本地免费 RIFE v4.6**，没有收费 API、云 GPU、付费软件或全局安装。内置生成消耗现有 Codex 额度，不代表无限免费。未运行 LoRA、ControlNet、IP-Adapter、EbSynth、ToonCrafter、BiRefNet 或 SAM，不宣称已完成整条约束链。

流程：原版中立参考 → 参考编辑关键帧 → 固定画布登记与静区像素保护 → RIFE → RGB/alpha 合成 → PNG/WebP → 技术与视觉门禁。使用官方 `nihui/rife-ncnn-vulkan` 20221029 便携版（MIT）；仅下载所需程序、模型，保存在 `.tool-tmp`。最终选择 Vulkan 设备 1（NVIDIA RTX 2070）。程序/模型哈希与真实参数在 `interpolation.json`。RGB 和 alpha 分开推理是本轮试验方法，不宣称已经正确解决透明传播。

### 视觉审查

Codex 主代理查看全部 78 张 PNG 的全帧联系表及固定眼部/手部放大图，并查看实际浏览器浅/深底、手机宽度截图；**不等于独立专业画师或所有者验收**。原始生成图存在静区漂移，未直接放行；调整后只保留眼部或指定手臂的变化，原版头身与脚部静止像素不变。挥手重做了一版，将手掌与头发拉开，并排除碰到头发的 05 关键帧及冗余 06 收手帧。

眨眼未发现阻断级裁切、变脸、双眼轮廓或明显外沿白边，闭合和重开可读。放大时原画及眼睑纹理略软，不宣称完美复刻。

挥手在抬臂、张掌和收手时出现灰色半透明手掌、重叠/融化轮廓，部分手掌接近消失。**零基 PNG 003–005、014–017、043–045、055–057 为阻断样例**。脚底、静区与边距通过仍不能放行；提高 30 fps 也不能修复。颜色和 alpha 两次推理运动场不一致是可能原因，不是已证明的唯一原因。

下一轮免费修正应先补抬手、握拳转张掌、收手的真实过渡关键帧，减小姿态跨度，并让颜色和 alpha 共用运动场；重新审完整动作。不要只增加播放帧数、整图交叉淡化或恢复分层骨骼。
