# 小助手自动动作与睡眠制作计划

小助手按对话和等待状态播放动作，不再要求访客点击动作按钮。调度完全在浏览器内完成，不新增模型请求，也不记录问题或用户行为。原来的角色素材、固定画布和衣领铭牌保持不变。

## 自动动作规则

| 时机 | 动作 | 频率保护 |
| --- | --- | --- |
| 打开对话 | 挥手 | 一分钟内只问候一次 |
| 查询等待超过 0.6 秒 | 思考 | 单次播放，继续等待时每 12 秒最多一次 |
| 有公开文章来源的正常回答 | 点头 | 回答反应至少间隔 8 秒 |
| 简短对话中的感谢 | 鞠躬致谢 | 同上 |
| 简短对话中的开心表达 | 小小庆祝 | 同上 |
| 75 秒未与助手互动 | 打哈欠 | 两次哈欠至少间隔 120 秒 |
| 无依据、低可信回答或错误 | 中立待机 | 不用庆祝或点头暗示答案可靠 |

输入、发送、清空、关闭和打开助手都会更新互动时间。输入时可打断闲置哈欠，回答可打断等待动作。页面隐藏、手动暂停或系统偏好减少动态效果时暂停动作，返回页面不补播错过的动作。键盘焦点、取消请求、静态降级和手机布局仍保留。

## 床上睡眠制作计划

这部分是新素材制作计划，不属于当前已验收的七个动作。只在对话关闭且 120 秒未与助手互动时进入长待机：先在第 75 秒复用已有哈欠，再等待约 45 秒。

新视频预算严格为 13 秒，按可灵当前界面每秒 6 灵感值，共 78 点。入睡 8 秒消耗 48 点，起床 5 秒消耗 30 点，720p、每段一个结果、关闭音画同步，不付费重试。

两段原片已生成，共使用 78 点，界面剩余 0 点。下载目的地被浏览器拦截，尚未取回本地原片；平台预览不能替代完整逐帧审查。生成记录见 `sleep-generation/plan.json`。睡眠动作当前未部署，待原片下载、抠图、接缝检查和点击唤醒接入后再验收。

入睡片在前半段拖入低矮小床、坐下并侧躺，最后约 2.5 秒保持睡姿，仅轻微呼吸。睡眠循环由稳定末段提取，可以一直睡到访客点击助手。起床片使用实际睡眠末帧作为首帧、原角色站姿作为尾帧；起床后连接已有哈欠，再回到普通待机。两次哈欠和睡眠循环不消耗新生成额度。

床比站姿更宽，必须使用覆盖整段运动范围的固定画布，不能套用旧站姿裁剪框。检查头身比例、衣领铭牌、手脚关节、床沿接触、遮挡关系、细闭眼线条、人物和床的完整边缘，以及循环接缝。背景抠图和网页素材打包完成后才可接入；原片生成成功不等于上线验收通过。

## 复用和验证

调度位于 `src/lib/assistant/behavior.ts`，时间参数集中管理；绘图仍使用已有整帧序列。更换形象时，只需替换通过审查的动作资源与时间线，保留事件和频率规则。睡眠道具动作应独立扩展，避免把新裁剪规则写进七个旧动作。

运行 `scripts/verify-assistant-behavior.mjs` 可在 1280、768、390 和 320 像素宽度验证自动事件、七个动作的全部 578 个原生绘图位置、资源哈希、固定视口、静态降级、暂停、取消和焦点。测试答案在浏览器中拦截，不请求真实 AI；时间推进是确定性逻辑测试，不代表物理设备帧率测试。
