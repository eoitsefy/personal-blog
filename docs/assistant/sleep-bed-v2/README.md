# 小助手睡眠和起床动画

这套素材在原来的七个动作之外增加拖床入睡、循环睡眠和点击起床。人物与床使用整帧原片，透明处理不重绘五官、不拆分肢体、不改变运动轨迹。原来的七个动作资源保持不变。

## 互动规则

对话关闭且 75 秒没有与助手互动时，先播放已有哈欠；到 120 秒播放约 8 秒入睡动作。睡着后使用 4 秒闭眼呼吸片段无限循环。第一次点击只唤醒助手，约 5 秒起床后接已有哈欠，再恢复普通待机；再次点击可以打开对话。入睡中点击会排队唤醒，不会突然跳回站姿。

对话打开、页面隐藏、手动暂停或系统减少动态效果时，不启动新的入睡动作。隐藏页面暂停睡眠时钟，返回时不补播。静态模式下可点击回到站姿；素材加载失败也会恢复可用的对话入口。所有调度均在浏览器内完成，不请求模型、不增加 AI 用量。

浏览器偏好切换通知偶尔可能延迟。播放器同时在绘图循环中检查实际偏好值，起床途中切换为减少动态效果时会安全落到站姿，不依赖单次通知。

## 素材来源和处理

可灵两段原片共使用已授权的 13 秒额度，即 78 灵感值；本地处理没有新增生成或付费。原片实际为 960 × 960、24 帧每秒，入睡 193 帧、起床 121 帧。原片哈希保存在 `manifest.json`，下载和额度记录保存在 `../automatic-behavior-v1/sleep-generation/plan.json`。

固定画布为 960 × 960，所有帧统一缩放至 480 × 480。小床独立使用宽画布，不能套用旧站姿裁剪框，也不按每帧人物边界重新居中。睡眠循环取入睡片第 144 至 192 帧，反向再正向播放，首尾相邻；起床从入睡末帧对应的睡姿开始。

原片背景有黑灰变化。U2net 单独分离的候选包因地面黑块被淘汰，BiRefNet 单独分离的候选因床沿闪缺被淘汰。最终使用本地 BiRefNet 整帧分离，并以原片中有颜色依据的轮廓补足道具透明度；不填充人物与床之间的背景空洞。柔边只去除背景混色，保留原片不透明区域的颜色。

画面角落的可见水印按此前授权在透明背景处理时排除，原片保留不动；发布 WebP 仍标记 Kling AI 来源。处理模型只用于本机离线制作，不进入服务器依赖，也不上传网站数据。

## 可复用制作流程

1. 保留下载原片，提取原生 PNG 序列并生成逐帧哈希，不用有损视频作为中间格式。
2. 用 `prepare-kling-sleep.py` 建立来源清单和外部轮廓候选，再用 `matte-kling-sleep-birefnet.py` 分离整帧。模型权重哈希必须与记录一致，关闭在线自动下载。
3. 用 `refine-kling-sleep-alpha.py` 补足颜色支持的道具边缘。检查背景负空间，不用整体填洞或逐帧移动素材。
4. 用 `review-kling-sleep.py` 输出每 24 帧一板的浅深背景图、完整动画与循环接缝。检查全部帧，不能仅抽查关键帧。
5. 用 `package-kling-sleep.mjs` 生成不可变版本的静态 WebP 分页。每页最多 24 帧，单文件小于 1 MiB；播放器只保留当前页和下一页，最多约 42.2 MiB 的解码页像素。
6. 运行单元测试、构建、`verify-assistant-sleep.mjs` 和旧动作回归。素材、逐帧像素和运行代码分别绑定哈希，再记录美术和浏览器验收。

更换角色时可复用闲置计时、点击唤醒、暂停、回退和分页播放器；需要重新制作角色原片、透明处理和视觉检查。若新角色或道具的范围变化，应重新校准一次全段固定画布，不继承旧角色的逐帧裁剪偏移。

## 验证范围

`review/art-review.json` 记录全部 314 帧在浅深背景下的视觉检查，原生快速转头的少量运动模糊保留。`review/boards` 保存全部检查板；三个动画预览与循环接缝图也在该目录中。

本地睡眠测试在 1280、768、390、320 像素宽度各检查 410 个播放位置，覆盖无限睡眠、点击起床、入睡中点击、对话阻止入睡、后台暂停、静态偏好和资源失败回退。专项测试主动阻断偏好变化通知，验证播放器仍能安全恢复静态状态。旧七动作在相同四种宽度各检查 578 个绘图位置。测试拦截 AI 请求，真实模型调用为 0；这不是实体手机帧率测试。

部署状态以 `review/production-deployment.json` 为准；只有生产复测通过后才标记已上线。

素材清单保留打包时状态，后续美术、浏览器和生产验收分别追加记录，不覆盖原始来源。代码指纹统一以 LF 换行计算，图片和像素指纹仍按原始字节计算。
